# BugVoice Notes Implementation Plan

Status: approved with maintainer amendments

> For agentic workers: Follow tasks in order. Each task starts with a failing test, then implements the listed interfaces, runs swift test, and commits only after the suite passes.

**Goal:** Add local Markdown notes with durable autosave, search/export, and private dictation into the note captured at recording start.

**Architecture:** Keep deterministic policy in Foundation-only VoiceCore: Markdown parsing/serialization, filename slug/collision rules, route-at-start and insertion placement, autosave policy, file-version hashing, search, and export. BugVoiceMac owns the single NotesStore actor and AppKit text-view insertion adapter. BugVoice owns page/controller wiring, menu actions, and application lifecycle. Notes dictation uses the existing transcription and cleanup providers but never changes ordinary app dictation behavior or persists its audio/result.

**Tech Stack:** Swift tools 6.0, macOS 15+, SwiftUI/AppKit, Swift Testing, WhisperKit 1.1.1 exact. No new dependency. VoiceCore imports Foundation only.

**Spec:** docs/superpowers/specs/2026-10-14-notes-design.md (approved with maintainer amendments). Read it before Task 1.

## Global Constraints

- Preserve existing dictation behavior outside the Notes route: configured language, cleanup, output bytes, history, secure-field policy, clipboard flow, Retry last, Paste last, and last.wav. Add a byte-for-byte ordinary-path regression test before changing shared controller/pipeline code.
- Select the Notes route only at run start. Once selected, bind the run to the captured note; focus loss does not cancel it or discard its transcript.
- Insert at the captured caret/selection if the note body revision is unchanged since run start; otherwise append to the body. Apply through the note buffer and NotesStore even if the editor is off screen. Discard only when the note no longer exists.
- Never use the paste target or pasteboard for a Notes dictation. Notes runs never write history, last.wav, or menu last-result state; Retry last and Paste last continue to refer only to ordinary dictations.
- One writer: every Notes file operation and write goes through one NotesStore actor. Keep directory reads, file I/O, file synchronization, rename, Trash operations, and directory sizing off MainActor.
- Durable note writes use a same-directory temporary file, file synchronization, atomic rename, and parent-directory synchronization. Detect external edits by modification time, byte size, and stable 64-bit FNV-1a content hash on selection, app activation, and before every save; do not poll.
- Body autosave debounces 500 ms. Title filename rename occurs only on Return or title-field focus out; body debounce keeps using the last committed title/path.
- One Notes insertion is one undo step, including when the editor is off screen and later reopened.
- Fold Notes immediate-save into the existing applicationShouldTerminate handler that handles the Meetings quit decision. Do not add another terminate handler.
- Store slug/collision, note-file parsing, routing/insertion placement, autosave debounce, external-version comparison, search, and Markdown export decisions in VoiceCore with tests.
- No new dependencies. Use Scripts/build-app.sh for the final signed app build. Do not merge or push. Do not commit .planning/; it is scratch and is ignored.

## Review Focus

1. **Private Notes dictation.** Start routing depends on BugVoice/frontmost/page/editor/selection/save-state only at start. Later focus changes cannot redirect or cancel the run. Verify unchanged-note selection insertion, changed-note append, off-screen buffer application, deleted-note discard, and no pasteboard access.
2. **Ordinary dictation regression.** A recording begun outside BugVoice follows the same provider/style/output bytes, paste target, secure-field decision, history, and last.wav behavior as before.
3. **One file owner and durable writes.** Every file operation routes through NotesStore. Saves cannot race older body debounce against newer title rename or insertion. Confirm temp file, file sync, atomic rename, and directory sync order.
4. **External edits.** Compare mtime, size, and FNV-1a hash on note selection, app activation, and every save. Clean note buffers reload; dirty buffers require Reload or confirmed Keep mine. No periodic watcher/poll loop.
5. **Markdown compatibility.** Parse leading H1 files, non-H1 files, and empty files. External files without a leading H1 use a filename-derived title and whole-file body; opening alone never rewrites them.
6. **Title and autosave timing.** Body save deadline resets to 500 ms after each edit. Title changes do not rename during editing or body debounce; Return/focus-out commits the title and path.

### Task 1: VoiceCore note model, Markdown parsing, and slug policy

**Files:** Create Sources/VoiceCore/Notes.swift, NotesDocument.swift, Tests/VoiceCoreTests/NotesDocumentTests.swift; edit Sources/VoiceCore/AppPaths.swift.

**Interfaces:** Define a stable NoteID, NoteDocument (title, body, slug/path identity, modification time, revision), and NoteFileVersion. Define NotesMarkdownDocument.parse(data:filename:) and .serialize(title:body:). Parsing recognizes a leading first-line H1 only when it begins exactly with "# " and has a nonempty title. For a missing/non-leading H1 or empty file, derive the title from the filename stem, replacing hyphens with spaces while preserving stem case, and retain the complete file contents as body; return whether the source needs normalization, but do not write during parsing. The first user edit serializes it with the canonical H1 + blank line + body format.

Define NotesSlug.make(title:) with canonical Unicode decomposition, explicit Đ/đ-to-d mapping, POSIX case/diacritic folding, ASCII lowercase alphanumeric runs joined by hyphen, trim, and "note" fallback. Define a pure collision allocator over case-insensitive existing .md names: base, then -2, -3, etc.; renaming to the note's own current slug does not allocate a suffix.

**Step 1 — Write failing tests first:** H1 parse including empty title handling, body preservation/newlines, non-H1 and empty-file filename-derived title, no normalization until edit, canonical serialization; Vietnamese "Đường đi" → "duong-di"; accented Latin, punctuation, whitespace, non-ASCII fallback, empty slug; case-insensitive collisions, suffix progression, rename-self, and stable NoteID across rename. Include the explicit empty/invalid H1 behavior: treat the first line as body if its H1 title is empty.

**Step 2 — Implement:** Keep all parsing and slug/collision logic Foundation-only and deterministic. Do not access the filesystem in these types.

**Step 3 — Verify:** swift test --filter NotesDocumentTests, then swift test.

**Step 4 — Commit:** feat(core): model notes and canonical Markdown filenames plus trailer.

### Task 2: VoiceCore route and insertion policies, search, and export

**Files:** Create Sources/VoiceCore/NotesPolicy.swift, NotesListProjection.swift, NotesExport.swift and their VoiceCore tests; extend DictationPipeline.swift and Tests/VoiceCoreTests/DictationPipelineTests.swift only after adding ordinary-path regression coverage.

**Interfaces:** Define a pure NotesRouteSnapshot/NotesRoutePolicy that chooses the Notes target at start only if BugVoice is active/frontmost, Notes is selected, the matching editor is first responder with a valid selection, and no save/conflict state blocks editing. Define NotesInsertionPlan using captured NoteID, captured body revision, captured selection, current note existence/revision, and editor visibility. It returns discard only when the note is deleted; it chooses the captured selection when the revision is unchanged, otherwise body-end. Visibility determines whether the AppKit editor or off-screen note buffer applies the same edit, not the insertion offset.

Define NotesListProjection search over title/body as literal case- and diacritic-insensitive substring; blank query returns all notes; order newest modified first then case-insensitive title. Define NotesExporter.markdown(title:body:) for exact canonical UTF-8 Markdown.

Add an explicit DictationPipeline Notes mode that forces document style and sends the final text only to the injected in-app target. It bypasses end-focus secure-field clipboard handling, never invokes InsertionTarget.copy, and returns a Notes-specific outcome. The ordinary mode remains unchanged. The app controller, not AppModel.record, owns the decision that Notes results never enter history/last-result state.

**Step 1 — Write failing tests first:** Route policy positive case and each failed start condition; route selection occurs once and later focus changes cannot change target. Insertion plans for unchanged revision at captured selection, changed revision at body end, unchanged off-screen editor at captured selection through buffer, and deleted note discard. Search literal/case/diacritic matching, blank query, body/title matches, and deterministic tie order. Exact Markdown H1/body bytes and Vietnamese UTF-8. Pipeline Notes mode forces document style, never copies when focus later appears secure, and emits no ordinary paste outcome. Add a regression test proving ordinary mode still produces the same final text/outcome and invokes the ordinary insertion path.

**Step 2 — Implement:** Keep route and placement as pure VoiceCore policy. Do not infer the route again at transcription completion. Keep ordinary pipeline control flow unchanged behind its default mode; add a narrow Notes branch for result disposition and insertion.

**Step 3 — Verify:** swift test --filter NotesPolicyTests; swift test --filter NotesListProjectionTests; swift test --filter NotesExportTests; swift test --filter DictationPipelineTests; then swift test.

### Task 3: Autosave and external-version policy

**Files:** Create Sources/VoiceCore/NotesAutosave.swift and Tests/VoiceCoreTests/NotesAutosaveTests.swift; extend Notes.swift/NotesPolicy.swift tests as needed.

**Interfaces:** Define NotesAutosavePolicy with a 500 ms body-edit debounce deadline and an explicit committed-title operation that requests an immediate rename/save only on Return or title-field focus out. Define a monotonically increasing note revision rule so an older queued save cannot supersede a newer edit. Define a stable 64-bit FNV-1a fingerprint over file bytes and a version comparison that includes modification time, size, and hash. Define refresh triggers for selection, app activation, and before save; do not model a polling timer.

**Step 1 — Write failing tests first:** Inject a controllable clock and cover 499/500 ms boundaries, repeated body edits resetting the deadline, title edits not renaming on body debounce, Return and focus-out committing once, body debounce using last committed path, latest-revision-wins ordering, deterministic FNV-1a vectors, same-size/same-mtime content changes detected by hash, mtime/size changes detected, and refresh trigger set contains selection/activation/pre-save only.

### Task 4: Single-owner durable NotesStore actor

**Files:** Create Sources/BugVoiceMac/NotesStore.swift and Tests/BugVoiceMacTests/NotesStoreTests.swift; update Package.swift only if a testable support target is required; extend AppPaths creation in Task 1 as needed.

**Interfaces:** NotesStore is the only writer and owner of Notes directory reads, list, open, create, rename, durable save, external version checks, and move-to-Trash deletion. It consumes VoiceCore values/policies. The actor serializes operations by NoteID and revision. Use a same-directory unique temp file, synchronize all file bytes, atomically rename, then synchronize the parent directory. Before every save, compare mtime/size/hash against the version loaded/last saved. A clean external change refreshes the value; a dirty conflict is returned to the caller for explicit Reload or confirmed Keep mine. Check versions on selection and app activation; no polling. Keep all file operations off MainActor.

**Step 1 — Write failing tests first:** Temporary-directory tests for list/open/create, durable replacement and rename, title H1 and file path agreement, body save preserving last committed title, collision resolution inside serialized actor operation, file discovery without rewriting on open, clean external reload, dirty external conflict, confirmed overwrite/recreate path, deletion of only selected file, and preservation of newer revision when older save is delayed. Use an injectable filesystem/durability boundary where needed to assert file sync → rename → directory sync ordering and simulate failures.

**Step 2 — Implement:** One actor performs every note filesystem operation. On save failure, retain dirty state and prior durable version. Recheck external fingerprint immediately before replacement. Move user-confirmed deletes to Trash. Do not add a watcher/poll loop.

**Step 3 — Verify:** swift test --filter NotesStoreTests, then swift test.

**Step 4 — Commit:** feat(app): add durable single-owner note storage plus trailer.

### Task 5a: Loaded-note source of truth, insertion, and undo

**Files:** Create Sources/BugVoiceMac/NotesController.swift, NotesEditorInsertion.swift, Tests/BugVoiceMacTests/NotesControllerTests.swift and NotesEditorInsertionTests.swift; extend NotesStore.swift and NotesStoreTests.swift.

**Interfaces:** NotesController owns an authoritative in-memory buffer for each loaded note. A loaded-note insertion mutates that buffer and, when visible, the NSTextView; it increments the note revision and schedules the regular 500 ms save. NotesStore applies an insertion directly only when the note is not loaded. NotesStore writes return the resulting file version to NotesController so the controller updates its baseline and does not classify its own save as an external edit.

NotesController owns one NSUndoManager per loaded note for the current app run. Supply it to the text view through undoManager(for:). Keep it registered when the editor goes off screen and register an off-screen insertion on the same manager, so reopening the note can undo once. Undo history resets at app relaunch. Before an insertion, refresh external changes and apply the VoiceCore NotesInsertionPlan. If the note changed since capture, append to the newest known body. If deleted, reject the insertion.

**Step 1 — Write failing tests first:** Test an insertion while a 500 ms body save is pending; both the typed edit and dictated text must remain in the buffer and durable file. Test that a NotesStore save followed by selection/activation refresh does not show Changed outside BugVoice. Test a loaded note is mutated by NotesController and NotesStore's direct insertion path is used only for an unloaded note. Test captured-selection insertion, changed-revision append, exactly one undo for visible and off-screen insertion, reopening retains the per-note manager during the app run, and undo history is absent after controller recreation.

**Step 2 — Implement:** Route every loaded-note edit/insertion through NotesController's buffer, then its existing save path. Store result versions after every successful actor write. NotesStore's direct insertion checks loaded state and file existence atomically. No file operation escapes NotesStore.

**Step 3 — Verify:** swift test --filter NotesControllerTests; swift test --filter NotesEditorInsertionTests; swift test --filter NotesStoreTests; then swift test.

**Step 4 — Commit:** feat(app): keep loaded note edits in one undoable buffer plus trailer.
