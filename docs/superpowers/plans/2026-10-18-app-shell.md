# App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the main window's flat `NavigationSplitView` with the mockup's shell: grouped full-height sidebar, a title bar with search and page action, section lists, round pills, centered content, ⌘K search, and Coming soon pages for Integrations and Help.

**Architecture:** Pure layout math (column caps, minimum window width, gutters) and search ranking (BM25 per item, title and settings matches, current-page-first order, snippets) live in `VoiceCore` with Swift Testing tests. The app side is a custom two-panel SwiftUI layout inside the existing AppKit-owned window; pages stop drawing their own titles and hand their action to the title bar.

**Tech Stack:** Swift 6 package, SwiftUI + AppKit, macOS 15, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-10-18-app-shell-design.md` (mockup `docs/design/proposal-appearance.html#shell`). Read both.

## Global Constraints

- No new dependencies.

## Review Focus

1. 160% text on the minimum window: title bar title, search, and split button never overlap; sidebar scrolls; pills wrap. Pinned by `ShellLayoutTests` (Task 1) plus the screenshot step in Task 6.
2. Vietnamese with and without diacritics: "tieng viet" finds "Tiếng Việt" in notes, meetings, dictations, and titles. Pinned by `GlobalSearchTests.foldsDiacritics` (Task 2).
3. Meetings still recording or transcribing (no passages) are found by title only and open without a line. Pinned by `GlobalSearchTests.unfinishedMeetingMatchesByTitle` (Task 2); Task 9 handles the nil line.

  }

### Task 2: Global search ranking (VoiceCore)

**Files:**
- Create: `Sources/VoiceCore/GlobalSearch.swift`
- Test: `Tests/VoiceCoreTests/GlobalSearchTests.swift`

**Interfaces:**
- Consumes: `AskPassage`, `AskSource`, `AskPart`, `AskLine`, `AskRanking.wordScores(_:terms:people:)`, `AskText.fold`, `AskText.tokens`, `MeetingID`, `NoteID` (all existing).
- Produces:
  ```swift
  public enum SearchKind: String, Sendable, CaseIterable { case meeting, note, dictation, settings }

  public struct SearchHit: Equatable, Sendable, Identifiable {
      public enum Target: Hashable, Sendable {
          case meeting(MeetingID, part: AskPart?, lineID: String?)   // part/line nil for a title-only match
          case note(NoteID)
          case dictation(UUID)
          case settings(section: String)                           // SettingsTab raw value
      }
      public var target: Target
      public var kind: SearchKind
      public var title: String        // meeting/note title; dictation app name or "Dictation"; settings label
      public var snippet: String      // "" when nothing to show
      public var date: Date?
      public var score: Double
      public var id: String           // stable per target
  }

  /// A meeting or note title, also for meetings with no passages yet.
  public struct SearchTitle: Sendable {
      public var source: AskSource    // .meeting or .note only
      public var title: String
      public var date: Date
      public init(source: AskSource, title: String, date: Date)
  }

  public struct SettingsSearchEntry: Sendable, Equatable {
      public var label: String
      public var section: String      // SettingsTab raw value
  }

  public enum GlobalSearch {
      public static let limit = 8
      public static let settingsEntries: [SettingsSearchEntry]
      public static func search(
          _ query: String, passages: [AskPassage], titles: [SearchTitle],
          first: SearchKind?, limit: Int = limit
      ) -> [SearchHit]
      public static func snippet(_ text: String, query: String, maxLength: Int = 90) -> String
  }
  ```

Rules (the tests pin them):
- Terms are `AskText.tokens(query)` each as its own term. Empty after trimming: `[]`.
- Passage scores from `AskRanking.wordScores(passages, terms:, people: [])`. Meeting and note: one hit per source, its best passage (ties: lower `index`). Dictation: one hit per passage; the entry UUID is the passage's line id (`AskPassageBuilder.passages(dictations:)` sets it).
- Title match: every query token is a prefix of some token of `AskText.tokens(title)`. Adds `5` to that item's score; a title-only match has `part: nil, lineID: nil` and snippet "".
- Note title passages (`part == .title`) do not become snippets; if a note's best passage is its title, use the next best body passage for the snippet, or "".
- Settings: same prefix rule over `label`; score `1`; title = label; snippet = section title is the app's job, so snippet "".
- Meeting hit: `part` = best passage part, `lineID` = its first line id when `part == .transcript`, else nil.
- Order: hits whose `kind == first` before the rest; inside each part, score descending, then date descending, then `id`. Cut to `limit`.
- Snippet: whitespace collapsed; window of `maxLength` characters around the first folded match of any token; `…` prefix/suffix when cut; whole text when shorter; first `maxLength` characters plus `…` when no token matches.
- `settingsEntries` holds exactly, in this order: section names `General→general`, `Shortcuts→shortcuts`, `Editing→editing`, `Theme & icons→theme`, `Speech→speech`, `Models→models`, `Agents→agents`, `Meetings→meetings`, `Storage→storage`; labels `Text size→editing`, `Font→editing`, `Code font→editing`, `Line spacing→editing`, `Reading width→editing`, `Theme→theme`, `Light and dark→theme`, `App icon→theme`, `Menu bar icon→theme`, `Recording pill→theme`, `Hold to talk→shortcuts`, `Hotkey→shortcuts`, `Paste last dictation→shortcuts`, `MCP server→agents`.
